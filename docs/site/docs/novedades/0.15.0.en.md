# What's new in 0.15.0

<small>In development: not published yet. This page describes what is already
implemented in the repository; the date and the versions will be added when the
release ships.</small>

0.15.0 lets you **deploy the agent you already have to Amazon Bedrock AgentCore
Runtime** with the same command as 0.14 and one more option:
`--target agentcore`. The default target is still a MicroVM fleet, and nothing
changes for anyone who does not use it.

Everything that costs money is still off by default: without
`--target agentcore` nothing is created and no AgentCore, CodeBuild or ECR client
is loaded, and `--dry-run` makes no AWS call.

## An agent on AgentCore { #un-agente-en-agentcore }

=== "CLI"

    ```bash
    rayito agent deploy ./my-agent --target agentcore --dry-run   # the plan, the security notes and the cost; no AWS call
    rayito agent deploy ./my-agent --target agentcore \
      --bedrock-model us.anthropic.claude-haiku-4-5-20251001-v1:0
    rayito agent invoke my-agent "Summarize the README." --target agentcore
    ```

=== "Python"

    ```python
    from rayito import AgentCoreOptions, AgentDeployOptions, deploy_agent

    fleet = deploy_agent(
        "./my-agent",
        options=AgentDeployOptions(bucket="amzn-s3-demo-bucket"),
        target="agentcore",
        agentcore=AgentCoreOptions(
            bedrock_models=("us.anthropic.claude-haiku-4-5-20251001-v1:0",),
        ),
    )
    reply = fleet.invoke("Summarize the README.")
    print(reply.text, reply.session_id)
    ```

=== "TypeScript"

    ```ts
    import { deployAgent } from "rayito";

    const fleet = await deployAgent("./my-agent", {
      options: { bucket: "amzn-s3-demo-bucket" },
      target: "agentcore",
      agentcore: {
        bedrockModels: ["us.anthropic.claude-haiku-4-5-20251001-v1:0"],
      },
    });
    const reply = await fleet.invoke("Summarize the README.");
    console.log(reply.text, reply.sessionId);
    ```

Rayito builds the `linux/arm64` image in CodeBuild (**no local Docker**), pushes
it to Amazon ECR, creates a least-privilege execution role, creates or updates
the runtime idempotently (deploying again is an update, never a duplicate),
waits until it is ready and enables MMDSv2, which AgentCore requires since
2026-06-30. `fleet.invoke()` and `fleet.stream()` have the same signature and the
same sessions as a MicroVM fleet. Details in
[Deploy to AgentCore](../guias/desplegar-en-agentcore.md).

It works with every framework the 0.14 detection already deploys: LangGraph and
LangGraph.js, LangChain and deepagents, Strands and its harness, Hermes,
OpenCode, the Vercel AI SDK and your own Flask or Express app.

## The security difference { #la-diferencia-de-seguridad }

AgentCore **has no Rayito secrets gateway**: the agent gets credentials from the
runtime role, and any code running in the session can read them. Inside a Rayito
MicroVM that does not happen. That is why the role Rayito creates is least
privilege: it only invokes in Bedrock the models of `--bedrock-model` and only
reads the secrets of `--readable-secret`. The plan the CLI prints, the README of
the exported context, the guide and [Security](../security.md#agentcore) say so in
the same words.

## Operating the agents { #operar-los-agentes }

| Command | What it does |
|---|---|
| `rayito agent status NAME --target agentcore` | the runtime's state, version, image and logs |
| `rayito agent list --target agentcore` | the region's Rayito agents |
| `rayito agent stop NAME --target agentcore --session-id ID` | ends one session's microVM |
| `rayito agent delete NAME --target agentcore` | deletes the runtime, the stack with its ECR repository and the log group; only what Rayito created |

`AgentCoreFleet.connect(name)` does the same from the SDK, and `--tag K=V` passes
tags to the stack and the runtime if your organization requires them.

## What does not apply to AgentCore { #lo-que-no-aplica-a-agentcore }

The options that size a MicroVM fleet (`min_vms`, `max_vms`, `warm_vms`,
`memory_mib`, `--port`, `--idle`, `--secret`, `--token-file`…) do not exist on
AgentCore: in the call they are an error (`option_not_supported`) and in the
project file a warning in the plan. Rayito never approximates them silently. The
[full table](../guias/desplegar-en-agentcore.md#opciones-que-no-aplican) says what
each one does.

## Changes to be aware of { #cambios-a-tener-en-cuenta }

There are no breaking API changes.

- **Exported context for AgentCore.** The `Dockerfile` of
  `rayito agent export --target agentcore` takes its base image from an
  `AGENT_BASE_IMAGE` build argument (with the same digest-pinned reference as the
  default) and the `README.md` explains how to deploy it. The `Dockerfile` and
  `README.md` of the `docker` target are unchanged.
- **Once, the image of your MicroVM agents is rebuilt.** The agent host and, for
  Node frameworks, the `node_bridge.mjs` bridge now carry the AgentCore support
  (session id and role credentials). They are part of the build context, so the
  first `deploy_agent` after upgrading creates one new image version (about
  $0.011 and at least one week of snapshot storage) even though your code did
  not change; later ones reuse it.
- **TypeScript: four new optional peers** (`@aws-sdk/client-bedrock-agentcore-control`,
  `@aws-sdk/client-bedrock-agentcore`, `@aws-sdk/client-codebuild` and
  `@aws-sdk/client-ecr`), which are only needed with `target: "agentcore"`.
- **A new exception**, `AgentCoreException` / `AgentCoreError`, with a closed
  list of `code` ([Errors](../referencia/errores.md#agentcore)).
- **A CDK construct is left for another change.** It blocks nothing here.

## How to try it { #como-probarlo }

1. Update the SDKs to the version that includes it and check the
   [region](../guias/desplegar-en-agentcore.md#antes-de-empezar) and the
   `rayito setup` bucket.
2. Add the [guide's permissions](../guias/desplegar-en-agentcore.md#antes-de-empezar)
   to the credentials of whoever deploys.
3. Try `rayito agent deploy ./my-agent --target agentcore --dry-run`.
