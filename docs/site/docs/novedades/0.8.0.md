# Borrador de 0.8.0

!!! danger "Esto no está publicado"
    Esta página es un borrador de las notas de una futura 0.8.0, escrito
    sobre el diseño ya aceptado de `ai-agent-core`, `ai-agent-fast-start` y
    `ai-agent-deepagents`
    ([`openspec/changes/`](https://github.com/alejandro-cedeno-10/rayito/tree/main/openspec/changes)).
    Ninguno de los tres cambios está fusionado en `main` todavía: nada de
    lo que describe esta página está disponible hoy, y el número de
    versión, los nombres y las cifras pueden cambiar antes de publicarse.
    No la enlaces como si fuera una release.

## Lo que trae (cuando se publique)

- **Un agente de código corriendo dentro del sandbox**: `sbx.agent.run()` /
  `.stream()` / `.prepare()`, con [OpenCode](https://github.com/anomalyco/opencode)
  por defecto o [deepagents](https://github.com/langchain-ai/deepagents) como
  alternativa, hablando con su modelo (Bedrock, Anthropic o un endpoint
  compatible con OpenAI) sólo a través de la
  [pasarela de secretos](../funciones-opcionales/pasarela-de-secretos.md).
  Sesiones, límites (`max_steps`, `max_total_tokens`, `timeout`), eventos en
  streaming y `abort()`, con paridad Python síncrono, Python asíncrono y
  TypeScript (iterador + `AbortSignal`).
  [Agente en el sandbox](../guias/agente-en-el-sandbox.md).
- **`AgentTemplate`**: una imagen con OpenCode, ripgrep y, opcionalmente,
  deepagents, con sus pines por sha256 y un prefetch de arranque que
  recorta el primer `exec`. [Templates de agente](../funciones-opcionales/templates-de-agente.md).
- **Calentamiento del pool (`warmup`)**: dos opciones para que una plaza del
  pool entregue el agente ya caliente (o con su servidor residente ya
  arrancado) en vez de pagar el primer `exec` al tomarla.
  [Pool: calentamiento y servidor residente](../pool.md#calentamiento-warmup-y-servidor-residente).
- **Coste**: el modelo, no la VM, domina el coste de un agente (7–20× en el
  ejemplo medido). [Coste de un agente](../cost.md#coste-de-un-agente-vm-frente-a-modelo).
- **Seguridad**: los permisos de un agente no son una frontera; la frontera
  sigue siendo el MicroVM más el egress cerrado.
  [Agente de código dentro del sandbox](../security.md#agente-de-codigo-dentro-del-sandbox).

## Qué falta antes de publicarla

- Fusionar `ai-agent-core`, `ai-agent-fast-start` y `ai-agent-deepagents`
  (dominio, adaptador de OpenCode, runner de deepagents, template, pool).
- La etapa de aceptación en AWS real (Q146–Q152 de `AWS_API_NOTES.md` §16):
  medir el prefetch, el calentamiento del pool con y sin servidor residente,
  reanudar en vez de crear, el runner de deepagents y la seguridad contra
  AWS real.
- Decidir, con esas medidas, si el prefetch queda encendido por defecto y
  si el servidor residente se recomienda sobre el calentamiento simple
  (las dos preguntas de diseño abiertas en
  [Pool](../pool.md#decision-de-diseno-pendiente-de-medir-en-aws)).

Hasta entonces, `sbx.agent` no existe en ningún SDK publicado.
