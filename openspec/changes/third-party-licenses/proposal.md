## Why

`rayd` statically links about 220 third-party crates for
`aarch64-unknown-linux-musl` (MIT, Apache-2.0, BSD-3-Clause, ISC,
Unicode-3.0, Zlib and the CC0 of `notify`). MIT, the BSD binary-form clause,
ISC and Zlib require their notices to travel with every binary copy, yet the
`rayd` release asset, `rayito-image.zip` and the image built from it carried
neither Rayito's own `LICENSE`/`NOTICE` nor any third-party notices file.
The 2026-10 OSS standards audit ranked this first
(`docs/research/2026-10-oss-standards-audit.md` §2.2 and §8 #1).

## What Changes

- **Generated notices**: `THIRD_PARTY_LICENSES.md` at the repository root,
  generated by `make licenses` with cargo-about 0.9.2 from `Cargo.lock` for
  `aarch64-unknown-linux-musl` (`about.toml` reuses `deny.toml`'s allowlist
  and its named `notify` CC0 exception; template `about.hbs`), with
  `--frozen` so the output depends only on the lock, the fetched crate
  sources, the policy, the template and the pinned tool. The file is not
  committed: `make image-licenses` regenerates it every time it is
  packaged (every `make image-zip*`, CI's `build` job and the release), so
  a `Cargo.lock` bump, Dependabot's included, needs no extra commit and no
  workflow ever writes to a pull request branch.
- **Coverage gates**: `make licenses` fails when the generated file's
  crates are not exactly the third-party crates `cargo tree -p rayd --target
  aarch64-unknown-linux-musl -e normal` compiles;
  `scripts/check_third_party_licenses.py` also fails when a listed crate is
  absent from the binary's `.dep-v0`, or ships a `NOTICE` file the root
  `NOTICE` does not carry. CI's
  `build` job and `release.yml`'s `rayd-build` run both. cargo-about comes
  from `.github/actions/cargo-about` (release binary pinned by sha256).
- **Shipped with every copy of rayd**: `LICENSE`, `NOTICE` and
  `THIRD_PARTY_LICENSES.md` go into `licenses/` of `rayito-image.zip`
  (`make image-licenses`; every `make image-zip*` target and the release
  stage them), `image/Dockerfile` copies them to `/usr/share/doc/rayd/`, the
  local guest context carries them, and the artifact builder refuses an
  image tree that ships `rayd` without them.
- **Release assets and signing**: the three files are `rayd-v*` release
  assets listed in `SHA256SUMS`; `rayd-sign` also signs `SHA256SUMS`
  (`SHA256SUMS.sigstore.json`, same exact identity, same approval gate), so
  the notices and the SBOM, which carry no bundle of their own, are covered
  by a signature. `rayd-upload` checks the bundle's digest too.
- **Docs**: `docs/RELEASING.md`, `docs/site/docs/verify.md`,
  `docs/site/docs/cli.md`, `SECURITY.md`, `CONTRIBUTING.md`, the audit
  (item marked done) and the `rayd` and Python changelogs.

Out of scope: the sidecar's Python dependencies are not redistributed by
this project (pip installs them inside the user's account at image build
time, and each wheel keeps its own `dist-info/licenses/`; pyzmq's includes
libzmq's unmodified MPL-2.0), so no pip-licenses output is shipped. No
release is cut; 0.7.0 and earlier stay as published.

## Impact

- Affected specs: `oss-licensing` (ADDED), `release-automation` (MODIFIED
  "rayd release artefacts carry an embedded dependency list, an SBOM and
  cosign bundles"), `cli` (ADDED).
- Affected code: `about.toml`, `about.hbs`, `.gitignore`,
  `Makefile`, `.github/actions/cargo-about/`, `.github/workflows/ci.yml`,
  `.github/workflows/release.yml`, `image/Dockerfile`, `.gitignore`,
  `clients/python/src/rayito/cli/_artifact.py`,
  `scripts/check_third_party_licenses.py` and tests.
- No runtime change in `rayd` or the SDKs. The image gains three text files
  under `/usr/share/doc/rayd/` (no snapshot change); the local guest build
  (`local-e2e.yml`) exercises the new `COPY`.
