## ADDED Requirements

### Requirement: Third-party notices travel with every copy of rayd
The repository SHALL commit `THIRD_PARTY_LICENSES.md` at its root, generated by `make licenses` with cargo-about 0.9.2 (`cargo about generate --frozen --fail -c about.toml -m crates/rayd/Cargo.toml about.hbs`) after `cargo fetch --locked`. `about.toml` SHALL filter the graph to `aarch64-unknown-linux-musl`, ignore build and dev dependencies and private crates, accept exactly the licenses of `deny.toml`'s `[licenses].allow`, and accept `CC0-1.0` only for `notify`. The file SHALL list every third-party crate as a line "- `<name> <version>`" under the full text of its license. `make licenses-check` SHALL fail when the committed file differs from a fresh generation and SHALL name `make licenses` as the fix. `scripts/check_third_party_licenses.py` SHALL fail when a crates.io package linked at run time in the `.dep-v0` section of the built `rayd` is not listed at the same version, and when a listed crate's source directory holds a `NOTICE` file whose crate the root `NOTICE` does not name. CI's `build` job and `release.yml`'s `rayd-build` SHALL run both, with cargo-about from `.github/actions/cargo-about` (release binary verified against a pinned sha256). `LICENSE`, `NOTICE` and `THIRD_PARTY_LICENSES.md` SHALL travel under `licenses/` in `rayito-image.zip` (`make image-licenses`, run by every `make image-zip*` target, CI and the release), SHALL be copied by `image/Dockerfile` to `/usr/share/doc/rayd/` (root, 0644) and SHALL be `rayd-v*` release assets.

#### Scenario: a lock change without regenerating
- **WHEN** a pull request bumps a crate in `Cargo.lock` and leaves `THIRD_PARTY_LICENSES.md` unchanged
- **THEN** `make licenses-check` in the `build` job prints the diff and fails, and `make licenses` produces the file that makes it pass

#### Scenario: a linked crate escapes the graph filter
- **WHEN** the built `rayd`'s `.dep-v0` names a crates.io runtime package that `THIRD_PARTY_LICENSES.md` does not list at that version
- **THEN** `check_third_party_licenses.py --binary` exits 1 naming the crate and version

#### Scenario: an upstream NOTICE appears
- **WHEN** a listed crate starts shipping a `NOTICE` file and the root `NOTICE` does not name the crate
- **THEN** `check_third_party_licenses.py --metadata` exits 1 naming the crate and the file

#### Scenario: the image carries the notices
- **WHEN** an image is built from a `rayito-image.zip` produced by `make image-zip` or the release
- **THEN** `/usr/share/doc/rayd/` holds `LICENSE`, `NOTICE` and `THIRD_PARTY_LICENSES.md`
