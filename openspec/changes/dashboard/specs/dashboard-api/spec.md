## ADDED Requirements

### Requirement: The dashboard core is hexagonal and has a pure domain
The dashboard SHALL define the ports `SandboxInventory`, `ImageCatalog`, `UsageCost`, `Quotas`, `EventsHistory` and `Actions`, with one adapter per AWS API and lazy imports of optional clients. The domain SHALL NOT import `boto3`, `@aws-sdk/*`, an HTTP library or generated proto code, and adapters SHALL translate technical errors to own exceptions mapped by code.

#### Scenario: domain has no infrastructure imports
- **WHEN** the dashboard domain modules are imported in an environment without `boto3`
- **THEN** the import succeeds

### Requirement: One versioned JSON API serves both phases
The API SHALL expose `/api/v1/sandboxes`, `/api/v1/images`, `/api/v1/quotas`, `/api/v1/cost`, `/api/v1/events` and `POST /api/v1/sandboxes/{id}/kill|suspend|resume`, with a schema versioned in the repository. The local server and the in-account Lambda handler SHALL pass the same contract tests.

#### Scenario: contract tests run against both shells
- **WHEN** the contract suite runs against the local server and the Lambda handler with the same fakes
- **THEN** both return identical response shapes

### Requirement: The dashboard never exposes secrets
Responses, logs and the SPA SHALL NOT contain tokens, JWE, `envs`, `runHookPayload` or secret values. The only sandbox metadata shown SHALL be the `metadata` field, from `metadata-index` or a Health probe; the probe JWE SHALL stay in memory and `envs` and the raw `runHookPayload` SHALL never enter the domain model.

#### Scenario: sensitive fields are absent
- **WHEN** a sandbox with envs and a hook payload is listed through the API
- **THEN** no response field or log line contains those values

#### Scenario: only metadata is shown
- **WHEN** a sandbox with envs and metadata is listed
- **THEN** only the metadata appears

### Requirement: Dashboard thresholds and limits are named constants
Warning thresholds, cache TTLs, TPS, page sizes and polling intervals SHALL be defined in `limits.json` and generated by `gen_limits.py`.

#### Scenario: generated limits are current
- **WHEN** `gen_limits.py --check` runs
- **THEN** it exits 0

### Requirement: The SDK fleet service is read-only by default
`Fleet` SHALL refuse every action (kill, suspend, resume) unless it was constructed with `allow_actions=True` (`allowActions: true` in TypeScript), SHALL validate the action and the sandbox ids before any AWS call, SHALL queue the calls at or below the lower of the `apiTps` limit and the applied quota rate, and SHALL report a per-sandbox failure by AWS code only, without stopping the queue.

#### Scenario: actions refused without the option
- **WHEN** a bulk action is requested on a `Fleet` built without `allow_actions=True`
- **THEN** it raises before any AWS call

#### Scenario: a failure does not stop the queue
- **WHEN** one sandbox of a bulk kill fails with an AWS error
- **THEN** the others are still attempted and the failed one reports only its AWS code

#### Scenario: quota and capacity failures are per-sandbox too
- **WHEN** a bulk resume hits `ServiceQuotaExceededException` or `InsufficientCapacityException` on one sandbox
- **THEN** that sandbox is `failed` with that code and the rest of the queue still runs

#### Scenario: a failure without an AWS code reports one neutral code
- **WHEN** a sandbox fails with an error that carries no AWS code
- **THEN** it reports `UnknownError` in both SDKs

#### Scenario: a non-positive applied rate is refused
- **WHEN** a bulk plan is requested with an applied rate of 0 or less
- **THEN** it raises `InvalidArgumentException` (`InvalidArgumentError`) before any call
