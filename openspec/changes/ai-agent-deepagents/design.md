## Context

`ai-agent-core` defined the pure `AgentRuntime` port, the closed event
vocabulary and the application layer (`sbx.agent`). This change adds a
second adapter. Unlike OpenCode, deepagents is a Python library, so Rayito
ships the process that runs it: a runner script that speaks Rayito's own
JSONL protocol. Facts checked on 2026-10-06 with deepagents 0.7.22,
langchain 1.4.3 and langchain-aws 1.8.0 (the pins of
`requirements-deepagents.txt`):

- `create_deep_agent` always appends `AnthropicPromptCachingMiddleware` and,
  when `langchain-aws` is installed, `BedrockPromptCachingMiddleware`
  (`deepagents/graph.py`, `append_prompt_caching_middleware`). The Bedrock
  one sets `cache_control` in `model_settings`, and `ChatBedrockConverse`
  turns it into `cachePoint` blocks after the system prompt and on the last
  message, the same shape OpenCode uses.
- The graph's model node is `model` and the tool node `tools`;
  `stream(stream_mode=["messages","updates"])` yields `(mode, data)`.
  `usage_metadata.input_tokens` includes cached tokens; the cache split is
  in `input_token_details.cache_read` / `cache_creation`.
- A `wrap_tool_call` middleware sees `request.tool_call` (`name`, `args`,
  `id`) and may return a `ToolMessage` instead of calling the tool.
- deepagents tools: `ls`, `read_file`, `write_file`, `edit_file`, `glob`,
  `grep`, `execute`, `task`, `write_todos`.

## Decisions

- **D1 — The runner speaks Rayito events, not deepagents events.** The
  adapter stays a validator: `v` must be 1, `type` one of the event names
  plus `session`; anything else is ignored and counted. The runner may only
  declare `model_error`, `runtime_error` or `protocol_error`; any other
  reason becomes `protocol_error` (the SDK alone decides `timeout`,
  `max_steps`, `token_budget`…). `finish()` returns `Done` only on exit 0
  after `done` and a `session`.
- **D2 — Protocol on a private fd.** The runner `dup`s fd 1, points fd 1 and
  `sys.stdout` at stderr, and writes events to the copy. A user entry point
  that prints, or a tool's child process, cannot inject events.
- **D3 — Request on stdin, static spec in a file.** The prompt never goes
  in argv or `envs`. The config file is 0600 and its sha256 lets the
  application layer skip rewriting it, as with OpenCode.
- **D4 — Prompt caching off is a patch of a pinned helper.** deepagents
  0.7 has no switch; with `AgentModel(prompt_caching=False)` the runner
  replaces `deepagents.graph.append_prompt_caching_middleware` by a no-op
  before building the graph. Pinned in the template, covered by
  `make agent-runner-test`.
- **D5 — Permissions map to deepagents tool names.** `read→read_file`,
  `edit→write_file,edit_file`, `list→ls`, `glob`, `grep`, `bash→execute`,
  `task`, `todowrite→write_todos`. Only `bash` takes patterns, matched with
  `fnmatchcase` against the command; the last matching pattern wins and no
  match falls back to `default`. `DEFAULT_DENIED_TOOLS` are skipped because
  deepagents does not have them; naming one explicitly is an error.
  Permissions are not a security boundary (T29): the MicroVM with closed
  egress is.
- **D6 — Sessions in the VM.** `rda_<uuid4 hex>` ids are generated by the
  runner; history is `messages_to_dict` JSON written atomically with mode
  0600. A `session_id` that does not match the pattern is rejected by the
  SDK before any RPC and by the runner (`invalid_session_id`), so it can
  never become a path.
- **D7 — Unsupported options fail early.** `mcp` and `raw_config` are
  OpenCode configuration; `attach=True` needs a resident server deepagents
  does not have. All raise `InvalidArgumentException` before any RPC.
- **D8 — One runner source.** The TypeScript SDK embeds the same bytes,
  generated by `scripts/gen_agent_assets.py` (`--check` in CI), and a test
  in each SDK compares them.
- **D9 — Capability delta uses ADDED.** The design notes call this a
  modification of `ai-agent-runtime`, but that capability only exists in
  the unarchived `ai-agent-core`; the delta adds requirements to it, which
  archives cleanly after `ai-agent-core`.

## Risks / Trade-offs

- deepagents internals (node names, the caching helper) can change across
  minor versions → the pins are hash-locked and `make agent-runner-test`
  runs the real venv in CI on arm64.
- Steps of subagents are not steps of the main agent: their streamed chunks
  (checkpoint namespace with `|`) are ignored, so `max_steps` and the token
  budget only see the main agent's model calls.
