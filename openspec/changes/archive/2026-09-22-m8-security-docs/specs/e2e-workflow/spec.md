## MODIFIED Requirements

### Requirement: OIDC role template with least privilege on the test image
`infra/ci-oidc-role.yaml` SHALL be a CloudFormation template, `cfn-lint` clean and accepted by `validate-template`, that is not deployed by this change. It SHALL take the parameters `GitHubRepository` (default `alejandro-cedeno-10/rayito`), `GitHubEnvironment` (default `e2e`), `TestImageArns` (list), `CreateOidcProvider` (default `true`), `ExecutionRoleArn` (optional) and `RoleName`; SHALL create an `AWS::IAM::OIDCProvider` for `https://token.actions.githubusercontent.com` with client id `sts.amazonaws.com` only when `CreateOidcProvider` is `true`; and SHALL create a role whose trust policy allows `sts:AssumeRoleWithWebIdentity` only when `token.actions.githubusercontent.com:aud` equals `sts.amazonaws.com` and `token.actions.githubusercontent.com:sub` equals exactly `repo:<GitHubRepository>:environment:<GitHubEnvironment>`, with `MaxSessionDuration` 3600. The role's only policy SHALL allow `lambda:RunMicrovm`, `lambda:GetMicrovm`, `lambda:SuspendMicrovm`, `lambda:ResumeMicrovm`, `lambda:TerminateMicrovm` and `lambda:CreateMicrovmAuthToken` on `TestImageArns`, `lambda:ListMicrovms` on `*`, `lambda:PassNetworkConnector` on `arn:aws:lambda:<region>:aws:network-connector:aws-network-connector:*`, and `iam:PassRole` on `ExecutionRoleArn` only when that parameter is set; it SHALL grant no image, S3, quota or tagging action. `infra/README.md` SHALL document the deploy command and `make infra-lint` SHALL lint this template together with the egress connector template. `infra/README.md` SHALL describe that trust exactly: the `sub` of a job that declares an environment carries **no branch component**, so any workflow of the same repository, on any branch, that declares `environment: <GitHubEnvironment>` presents the accepted `sub`; the branch is closed outside IAM by pinning the environment's deployment branches to `main` when the environment is created (Settings → Environments → Deployment branches and tags → selected branches), stated next to the required reviewers in the post-deploy steps. `infra/README.md` SHALL NOT claim that another branch cannot assume the role, and SHALL name a `GitHubRef` parameter with a second `StringLike` condition on `repo:<GitHubRepository>:ref:refs/heads/main` as the IAM-side alternative, not as something the template already does.

#### Scenario: template lints clean
- **WHEN** `uvx cfn-lint==1.56.3 infra/ci-oidc-role.yaml` and `aws cloudformation validate-template --template-body file://infra/ci-oidc-role.yaml` run
- **THEN** both succeed with no findings

#### Scenario: another environment or another repository cannot assume the role
- **WHEN** a workflow of the same repository runs outside the `e2e` environment and calls `configure-aws-credentials` with the role
- **THEN** STS refuses the assumption because the `sub` claim does not match `repo:alejandro-cedeno-10/rayito:environment:e2e`

#### Scenario: the README states what the trust does not cover
- **WHEN** `scripts/tests/test_security_docs.py::test_oidc_trust_has_no_branch_component` reads the OIDC section and the post-deploy steps of `infra/README.md`
- **THEN** the file says the `sub` carries no branch component, asks for the `e2e` environment's deployment branches to be pinned to `main`, and no longer says that another branch cannot assume the role
