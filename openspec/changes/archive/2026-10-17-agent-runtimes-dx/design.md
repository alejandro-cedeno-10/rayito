## Context

The 0.14 host (`agent_host`) is a stdlib-only program copied into the agent
image; the SDK writes `host.json` and starts it. The in-VM files are shared by
both SDKs (the TypeScript copy is generated by
`scripts/gen_agent_template_assets.py`), so a host change is made once.

## Decisions

### D1. The environment is host options, not image changes
`CustomRuntime.host_setup` adds `app_dir` (`AGENT_APP_DIR`) and, with
`requirements`, `path_prepend` (the venv `bin`) to the `http-app` and `command`
driver options. The driver builds the child environment from them
(`child_environment`) and, only for `http-app`, uses `app_dir` as the working
directory. `command` keeps `workdir` as its working directory because existing
commands may write relative paths and the source directory is read-only for the
agent user. No image step changes, so existing image digests are stable and the
new behaviour arrives with the host files.

### D2. `python` is an alias of the host interpreter, only when absent
The base image ships `python3` but no `python`. When `argv[0]` is `python` and
none is on the child `PATH`, the driver substitutes `sys.executable` (the
interpreter running the host: the venv one with `requirements`, `python3`
otherwise). When a `python` exists on the `PATH` (the venv one) it is left alone.

### D3. Diagnostics are a marker format, redacted twice
The failed marker stays plain text: the first line is the code and the rest is
the diagnostics, so a 0.14 reader that prints the whole marker still works and a
new reader of an old marker sees only the code. The host redacts (control
characters, every non-structural environment value of 8 or more characters,
credential patterns, long token-like runs) and bounds the text before writing;
the SDK bounds it again. The stderr of an `http-app` child is read by a thread
that keeps only the last 8 KiB, so a noisy app cannot fill a pipe or memory.

### D4. `keep_on_failure` requires a known token
Keeping a sandbox nobody can open is useless and leaks cost. `deploy` therefore
raises `InvalidArgumentException` before creating anything unless an
`access_token` (argument or `RAYITO_ACCESS_TOKEN`) is known. The error carries the
sandbox id (never the token) as a note (Python `add_note`) or in the message
(TypeScript). `BaseException` (Ctrl-C) always kills.

### D5. Unknown usage is a flag, not a type change
`AgentResult.usage` stays a `TokenUsage`; `usage_reported` says whether it is
real. Making `usage` optional would break `result.usage.total` for every 0.13
caller. The default is `True`, so every runtime that reports usage and every
older service behaves as before; only a `step_finished` without a `usage` object
(HTTP app, `command` with `protocol="text"`, a callable that returns none) is
unreported. The service JSON adds `usage_reported`; absent means `true`.

### D6. LangGraph nodes by name, not by message type
The translator accepts `model` and `agent` as model nodes and `tools` as the
tools node. Translating by message type would also pick up middleware nodes of
deepagents (a patch node adds `ToolMessage`s) and change its events. A plain
`StateGraph` works when its nodes use those names; the docs say so.

### D7. `raw` is a choice, so it is advice and a warning, not a default flip
Switching the default protocol or auto-detecting would silently remove
`invoke()` from projects that rely on `agentcore` with custom `health_path` and
`invoke_path` (the host translates to them). The docs get a table; `HttpApp`
gets `hides_own_routes`; `rayito agent deploy` prints a warning when an app's
routes are hidden; and `init --runtime custom` writes `raw` because the scaffold
declares its own routes.

### D8. `--base-image-version latest`
The option stays required (a silent roll of the managed image must not change a
build), and `latest` resolves the newest listed version and prints the one it
chose. `newest_managed_version` moves from the doctor to `_publish.py` and both
use it.

## Risks

- A host change needs an image rebuild; the docs and CHANGELOG say so.
- The redaction patterns are heuristics; the diagnostics are bounded and a
  secret-free guarantee is only as good as the env-value rule plus the patterns,
  which is why the text is capped at 2 KiB and never logged by the host.
