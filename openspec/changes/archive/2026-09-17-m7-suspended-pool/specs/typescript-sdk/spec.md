## ADDED Requirements

### Requirement: Suspended-slot pool with the Python semantics
The package SHALL export `SandboxPool`, `PoolConfig`, `PoolStats`, `PoolSlotInfo`, `PoolBackend`, `InMemoryPoolBackend`, `JsonFilePoolBackend` and `PoolClosedError` (a `SandboxError` subclass) from `clients/typescript/src/pool/` with the semantics of the `sandbox-pool` capability: `PoolConfig` with `size`, `template`, `templateVersion`, `timeoutMs` (default 28 800 000), `idle` (must have `autoResume: true`), `envs`, `metadata`, `cpuTimeLimit`, `executionRoleArn`, `ingress`, `egress`, `logging`, `minRemainingMs` (default 3 600 000), `fillConcurrency` (default 4), `sweepIntervalMs` (default 30 000), `readyTimeoutMs`, validated by `validatePoolConfig` with the same rules and cap `1..=64`; `SandboxPool` with `start()`, `take({ waitMs, readyTimeoutMs, requestTimeoutMs, reconnectTimeoutMs })`, `stats()`, `close({ drain })` and `Symbol.asyncDispose`; a slot warmed with `Sandbox.create()` plus `pause({ wait: true })` plus `close()`, one fresh access token per slot, the record saved as `warming` right after `runMicrovm` and as `ready` after the park; `take()` selecting the oldest ready slot with enough life, deleting the record first, calling `resumeMicrovm`, opening with the slot's token and a 100 → 500 ms readiness schedule, never calling `getMicrovm` on that path, and falling back to a plain `create()` on an empty pool or a lost slot; the filler as a promise loop on an `AbortController` bounded by `fillConcurrency`, paced by the shared control plane's buckets, with the 1 s → 60 s backoff; the sweep with recycling under `minRemainingMs` and reconciliation through `listMicrovms`; recovery from a persistent backend at `start()`; `close({ drain: false })` rejected on a non-persistent backend; the same counters. `JsonFilePoolBackend` SHALL use `node:fs/promises`, write `<path>.tmp` with `mode: 0o600` then `rename`, and produce the `rayito.pool/1` schema of the Python backend. The sweep and backoff timers SHALL be `unref()`ed so an idle pool never keeps the Node process alive by itself. `Sandbox.create({ pool, ... })` SHALL return `pool.take(...)` and throw `InvalidArgumentError` naming the first launch or plane option that is set alongside `pool` (`template`, `templateVersion`, `timeoutMs`, `idle`, `envs`, `metadata`, `cpuTimeLimit`, `executionRoleArn`, `allowedPorts`, `ingress`, `egress`, `logging`, `region`, `client`, `accessToken`, `keepOnFailure`, `controlPlane`, `transport`). The pool SHALL log through the SDK `Logger` and never a token, a JWE, `envs`, `metadata` values or the payload.

#### Scenario: unit parity over the fakes
- **WHEN** `tests/unit/pool.test.ts` runs over the fake control plane and fake `rayd` of `tests/unit/fake/`
- **THEN** warm-up sequence and record contents, distinct tokens per slot, oldest-first take with `resumeMicrovm` and no `getMicrovm`, fallback with `misses`, lost slot at take, recycle with fake timers, reconcile drop/repark/check, backoff 1 s then 2 s, drain on `close()`, `drain: false` rejected in memory and accepted on the JSON backend, recovery, `Sandbox.create({ pool })` sugar and option rejection, stats arithmetic and "no secret in the logger output" all pass

#### Scenario: idle pool does not pin the event loop
- **WHEN** a unit test starts a pool over the fakes with fake timers, lets it fill and inspects the pending timers
- **THEN** every pending timer of the pool reports `hasRef() === false`

#### Scenario: guarded e2e through the TypeScript SDK
- **WHEN** `RAYITO_E2E=1 RAYITO_TEMPLATE=<arn> pnpm test:e2e` runs `tests/e2e/pool.e2e.test.ts` with `size: 2`
- **THEN** five takes, each issued after `stats().ready >= 1`, each answer `1+1` with `"2"`, each `take` → first cell duration is printed, `stats().hits === 5`, and after `close({ drain: true })` no VM of the template is `PENDING|RUNNING|SUSPENDING|SUSPENDED`
