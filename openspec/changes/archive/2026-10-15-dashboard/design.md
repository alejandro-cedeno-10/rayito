## Context

ADR-014 allows optional components in the customer account and forbids
Rayito-hosted services. ADR-016 defines `OptionalStack`. ADR-026 allows a
management dashboard under the same rules. Platform facts: `list-microvms`
returns only id, state, image, version and `startedAt` (no tags, no filters);
there are no native CloudWatch metrics for MicroVMs; Cost Explorer groups by
usage type (five `Lambda-MicroVM-*` types), not by MicroVM, with a 24 h lag
and $0.01 per request. The Python CLI is the only CLI.

## Decisions

- **D1 — Hexagonal core.** Ports `SandboxInventory`, `ImageCatalog`,
  `CostSource`, `QuotaSource`, `EventsHistory`, `Actions` (`Protocol` in
  Python, `interface` in TypeScript); the public SDK services are `Quotas`,
  `UsageCost` and `Fleet` (with `Async*` twins in Python), which compose the
  ports. `SandboxInventory` and `Actions` are structural subsets of
  `ControlPlane` (no new adapter) and `LifecycleEvents.get_events` is the
  `EventsHistory`. One adapter per AWS API (`lambda-microvms`, Cost Explorer,
  Service Quotas, CloudWatch Logs, DynamoDB) with lazy imports. The domain imports no `boto3`, HTTP or generated proto code.
  Adapters translate SDK errors to own exceptions by code, never by text.
- **D2 — One versioned API, one SPA.** `/api/v1/sandboxes`, `/images`,
  `/quotas`, `/cost`, `/events` and `POST /api/v1/sandboxes/{id}/kill|
  suspend|resume`. The schema lives in the repo and a contract test suite
  runs against both the local server and the Lambda handler. The SPA is ES
  modules and web components with no build step, ships inside the wheel,
  draws all colours, radii, fonts and spacing from CSS custom properties with built-in themes `rayito-dark` (default) and `rayito-light`, and supports a validated user theme (`parse_theme`, `parse_logo`: closed key list, strict value grammar, CSS generated by the panel) that the phase 2 stack receives as a parameter and serves from the same routes (`/theme.css`, `/theme/logo`).
- **D3 — Read-only by default.** Actions require `--allow-actions` (phase 1)
  or the actions role (phase 2), UI confirmation, and a queue that respects
  TPS (suspend 2, terminate 10, resume 5; read from Service Quotas when
  available). Bulk actions show progress. Actions are idempotent upstream.
- **D4 — Quotas.** The panel shows allocated memory (RUNNING plus SUSPENDED)
  against the per-region quota, warns at named thresholds in `limits.json`,
  shows the applied TPS per operation and links to the quota-increase flow in the console. Filing the request from
  the panel is out of scope: it would be a write action
  (`servicequotas:RequestServiceQuotaIncrease`).
  If Service Quotas does not publish utilization for MicroVMs, the panel
  computes it by counting VMs and image memory (to measure on AWS).
- **D5 — Cost.** Billed cost comes from Cost Explorer grouped by usage type,
  cached (TTL in `limits.json`), enabled only by an explicit option. Per
  sandbox cost is an estimate (active hours times size price) and is always
  labelled "estimated" next to the billed total.
- **D6 — Local security (phase 1).** Loopback bind, random port, `Host` and
  `Origin` checks, `Sec-Fetch-Site` (only `same-origin` or `none` reach
  `/api/v1`, because a page served by a sandbox through `rayito sandbox
  proxy` is same-site and sends no `Origin`) and CSRF protection reusing the
  `cli/_proxy.py` approach; the paid billed-cost `GET` also needs the CSRF
  token, and the proxy never forwards `rayito_dashboard_*` cookies to the
  guest. The CloudWatch logs helpers live in `rayito/_cloudwatch_logs.py` and
  the logs adapter in `rayito/_dashboard/_logs_aws.py`, so both shells share
  them.
  The start URL carries a one-time token. The first request swaps it for an
  `HttpOnly`, `SameSite=Strict`, `Path=/` session cookie and redirects to a
  clean URL; the token is then invalid, so history and `Referer` leak
  nothing. Every response sends `Referrer-Policy: no-referrer`. The printed
  start URL is the single deliberate exception to "never display tokens"; the
  token is never written to logs. Never display or log JWE, `envs`,
  `runHookPayload` or secret values.
- **D7 — In-account stack (phase 2), testable under restrictive org
  policies.** The SPA and API are served from one Lambda Function URL created
  by CloudFormation (direct `lambda:CreateFunction` and S3 bucket or
  CloudFront creation may be denied by policy, CloudFormation-created
  Lambdas work). A Function URL supports only two auth types, and a browser
  navigation cannot sign with SigV4, so there are two real variants:
  - **(a) Default: `AuthType NONE` plus handler-side Cognito JWT.** The
    static shell (HTML, JS, CSS) is the only unauthenticated route. Every
    `/api/v1/*` request is validated by the handler before any routing or AWS
    call: issuer, audience, expiry, signature against the JWKS and
    `token_use`. Login uses the Cognito Hosted UI with the authorization-code
    flow and PKCE; the SPA sends the token in the `Authorization` header.
  - **(b) Optional: `AuthType AWS_IAM` (`AuthMode=aws-iam`).** The SPA obtains
    credentials from a Cognito identity pool and signs its fetches with SigV4.
    The shell still needs an unauthenticated way to load, so the stack deploys
    two functions from the same zip: the API function behind an `AWS_IAM`
    Function URL (CORS for the page's origin only, no credentials, no
    resource-based permission with a `*` principal) and a page function behind
    a public URL whose role can only write logs and read the client list and
    SSM parameters. Because the API URL is the identity pool's target and the
    page URL is the Cognito callback, the page function reads the pool id and
    the API URL from an SSM parameter at run time (an environment variable
    would be a dependency cycle). The Cognito access token still travels, in
    `X-Rayito-Token` (the `Authorization` header carries the signature), and
    is validated as in (a), so groups, the live check and the audit are
    unchanged.
  Which one works on real AWS is verified in task 5.1b; variant (a) is
  the default and the working assumption, not a given.
  *Roles.* One function has exactly one execution role, so the function runs
  with a read-only role and an actions role is reached with `sts:AssumeRole`
  only after the handler checks the caller's Cognito group claim. The actions
  role trusts only the function role, with a session name carrying the caller
  subject. An audit row in DynamoDB per action (caller subject, action,
  resource, time) is written with a conditional put and no delete
  permission. Required tags pass through `deploy --tag`.
  *Cost Explorer.* Access is a stack parameter, off by default;
  `ce:GetCostAndUsage` is granted to the read role only when it is on.
  *Browser defences.* Function URL CORS allows only its own origin; `Origin`
  is checked on every `POST`; the token travels in `Authorization`, never in
  a cookie, so no CSRF token is needed; every response, SPA included, sends a
  restrictive `Content-Security-Policy`, `X-Frame-Options: DENY` with
  `frame-ancestors 'none'`, and `Referrer-Policy: no-referrer`.
  CloudFront plus S3 is an optional variant documented as untested where
  blocked.
- **D8 — Metadata.** The panel shows only the sandbox `metadata` field, read
  from `metadata-index` or from a Health probe. Without the index it costs
  O(n) probes; the panel says so and offers to enable the index. The per
  sandbox JWE needed for the probe is minted, kept in memory, cached per
  sandbox and never serialised to the API or logs. `envs` and the raw
  `runHookPayload` are never read into the domain model.
- **D9 — No magic numbers.** Warning thresholds, cache TTLs, TPS, page sizes
  and polling intervals are named constants in `limits.json`, generated by
  `gen_limits.py` into `_limits.py` and `limits.ts`.
- **D10 — Off by default.** No call and no peer import happens unless the
  command is run or the stack deployed. A golden-trace test per SDK proves
  zero billable calls, like `test_m15_zero_cost.py`.

- **D11 — CloudWatch dashboard, one generator.** `rayito._dashboard._cloudwatch_board` (pure) builds the `DashboardBody`: five Logs Insights widgets (plus a text header) over `/rayito/*` (lines and errors per interval, lines per group, noisiest streams, recent errors), the OTLP charts (`chart` widgets with PromQL over the CPU, memory and disk `rayito.sandbox.*` gauges) with `--otlp`, and the quota chart (a `metric` widget over the custom metric of D13 with the named thresholds as annotations) with `--quota`. Widgets carry no `x`/`y`, so optional ones leave no gaps. `infra/dashboard-cloudwatch.yaml` embeds the same JSON in a `Fn::Sub` with `If` fragments, written by `scripts/gen_cloudwatch_template.py` between markers and checked by a test, so printing and deploying cannot diverge. Untested on real AWS: `SOURCE logGroups(namePrefix:)` inside a widget and the PromQL form (OTLP metrics are not in `ListMetrics`).
- **D12 — Multi-account by assumed read roles, local only.** `--account NAME=ARN` (opt-in, capped in `limits.json`) builds one read-only `DashboardApi` per account over a session whose credentials come from `AssumeRole` (deferred refresh, so no STS call until used) and an `AccountsApi` wrapper that routes by `?account=`. The target account deploys `dashboard-read-role` (five reads, trusts one principal, optional `ExternalId`). Additional accounts get no actions, no Cost Explorer, no logs. The in-account stack does not include it yet (it would need its own role list parameter and a revocation story).
- **D13 — Quota alerts.** `infra/quota-alerts.yaml`: a CloudFormation Lambda (bundles the SDK `Quotas` service like `dashboard`) on an EventBridge `rate(...)`; the level is stored in a one-row DynamoDB table and an SNS message goes out only when it rises; the state is saved after the publish. It also publishes `Rayito/Dashboard` `MemoryAllocatedFraction` (dimension `Region`), the one custom metric (about $0.30/month) that the CloudWatch dashboard plots. One stack per region.

## Risks / Trade-offs

- Undocumented `ListMicrovms`/`ListMicrovmImages` TPS: conservative token
  bucket and caching until measured.
- Cost Explorer lag and per-request price: cache and clear labelling.
- Data-plane actions (extend timeout, live metrics) need a running VM and a
  JWE beyond the in-memory Health probe of D8; excluded from the first cut.
- Phase 2 attack surface: security review against `SECURITY.md` before
  publishing each phase.

## Open Questions

- Function URL with IAM auth versus Cognito JWT on real AWS.
- Whether Service Quotas exposes MicroVM utilization.
- Multi-region view: one region at a time versus bounded concurrency.
