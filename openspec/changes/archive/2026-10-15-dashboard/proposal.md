## Why

Operators of MicroVM fleets have no single view of what exists in their own
account: running and suspended sandboxes, images and versions, the real Lambda
MicroVMs quotas (memory per region, TPS), billed and estimated cost, and
lifecycle events. The data is reachable (`list-microvms`, Service Quotas,
Cost Explorer, `metadata-index`, `events-webhooks`) but only call by call.
`SPEC.md` listed "Billing, dashboard or any SaaS product surface" as a
non-goal, which literally forbids this even when it runs in the user's own
account. ADR-026 narrows the non-goal to billing and a Rayito-hosted panel;
this change plans and specifies the optional dashboard across all phases.

## What Changes

- **Phase 0 (this PR)**: ADR-026 in `ARCHITECTURE.md`, the `SPEC.md` §4
  sentence adjusted, and this OpenSpec change. No code.
- **Phase 1**: `rayito dashboard` (Python CLI, extra `cli`): a local server on
  `127.0.0.1` serving a versioned JSON API and a build-free SPA, read-only by
  default, with inventory, images, quotas, cost, events and gated actions.
- **Phase 1 SDK**: `Quotas` and `UsageCost` services in Python (sync and
  async) and TypeScript with the same surface, plus the pure domain and ports
  (`SandboxInventory`, `ImageCatalog`, `UsageCost`, `Quotas`,
  `EventsHistory`, `Actions`).
- **Phase 2**: `infra/dashboard.yaml` as an `OptionalStack` component: the
  same API and SPA served from a CloudFormation-created Lambda Function URL,
  with authentication, separate read and actions roles, a DynamoDB cache and
  an audit table. CloudFront plus S3 is an optional documented variant.
- **Phase 3 (optional)**: generated CloudWatch dashboard, multi-account read
  roles, quota alerts to SNS.
- Every threshold, cache TTL and TPS is a named constant in `limits.json`
  generated by `gen_limits.py`; docs in Spanish (Diátaxis) with the "Coste y
  activación" box; one row in `optional-features.md`.

## Capabilities

### New Capabilities

- `dashboard-api`: ports, pure domain and the versioned `/api/v1` JSON API
  shared by both phases.
- `dashboard-local`: `rayito dashboard`, the build-free SPA and the local
  security model.
- `dashboard-quotas-cost`: `Quotas` and `UsageCost` SDK services with parity.
- `dashboard-stack`: the in-account `dashboard` OptionalStack.
- `dashboard-cloudwatch`: phase 3 generated CloudWatch dashboard and alerts.

### Modified Capabilities

- `architecture-docs`: ADR-026 and the adjusted `SPEC.md` non-goal.

## Impact

- Docs: `ARCHITECTURE.md`, `SPEC.md`; later `docs/site/docs/guias/`,
  `referencia/`, `optional-features.md`, `mkdocs.yml` nav.
- Code (later phases): `clients/python/src/rayito/_dashboard/`,
  `rayito/cli/`, `clients/typescript/src/dashboard/`, `limits.json`,
  `infra/dashboard.yaml`, `OptionalStacks`.
- No `.proto` and no `rayd` change. Costs nothing unless activated.
