## Context

Rayito was developed and accepted against one AWS account from one Windows
workstation. Acceptance logs, benchmark data and defaults recorded that
environment literally. Before publication the tracked tree has to be neutral,
and a gate has to keep it neutral.

## Goals / Non-Goals

**Goals:**

- No account ID, account-bound bucket, SSO profile or role name, real
  resource ID, or local machine path in any tracked file.
- Measured numbers (latencies, sizes, costs) stay exactly as recorded.
- A stdlib gate over `git ls-files`, in `make lint` and CI, so it cannot come
  back.

**Non-Goals:**

- Rewriting git history (the owner publishes from a fresh history or decides
  separately).
- The GitHub org/repo slug, the maintainer handle, the example region
  `us-east-1` and the supported-region lists: owner decisions, kept.

## Decisions

### D1. Placeholders

- Account: `123456789012` inside ARNs (AWS documentation convention, already
  used by the unit tests); in prose the resource is described by name and the
  account as "una cuenta de pruebas" / "test account".
- Bucket: `amzn-s3-demo-bucket` in code, tests and fixtures; `<tu-bucket>` in
  Spanish shell examples, `<bucket>` in English task logs; pre-existing
  `<bucket>` / `<perfil>` placeholders are left as they are.
- SSO profile: `<tu-perfil>`; SSO role suffix: `<suffix>`.
- MicroVM: `microvm-<id>` in prose; `microvm-00000000-0000-0000-0000-<n>`
  (`<n>` as twelve decimal digits, numbered in order of first appearance) in
  data and fixtures. Twelve digits instead of two because one benchmark file alone
  holds 112 distinct IDs.
- Network: the foreign VPC's ID and CIDR are dropped from prose; examples
  keep `vpc-0123456789abcdef0`, `subnet-0123456789abcdef0`,
  `sg-0123456789abcdef0`.

### D2. No default bucket anywhere

`Makefile`: `BUCKET ?= $(RAYITO_BUCKET)` (make imports the environment, so
the same variable the CLI reads works) and a phony `require-bucket` target,
first prerequisite of every `image-publish*` target, whose recipe expands
`$(error …)` when `BUCKET` is empty. Recipe-time expansion keeps `make lint`,
`make test` and friends working without a bucket, and prerequisite order
stops the publish before `cargo zigbuild` runs. `spike/m0/run_m0.py` exits
with `set RAYITO_BUCKET …` at startup, like it already does for
`AWS_REGION`.

### D3. Raw spike output leaves the tree

`spike/m0/out/` is regenerated by `run_m0.py` and holds account, ARNs,
endpoints and IDs by nature; sanitizing it would destroy what makes it raw.
It is removed from the index (files stay on disk) and ignored as a whole.
`M0_RESULTS.md` keeps every measured value. The one consumer,
`test_doctor.py`, reads a sanitized copy of `quotas.json` (every quota
code, name, value, unit and adjustability identical; account replaced in
`QuotaArn`).

### D4. Raw benchmark JSON stays, sanitized in place

`docs/benchmarks/raw/*.json` backs every number of the benchmark report, so
it stays. A one-off text substitution (not a JSON round trip, so formatting
and numbers are byte-identical) maps each distinct real MicroVM ID to a fake
of D1 and the account to the placeholder; a check compares every numeric
value before and after.

### D5. The gate: `scripts/check_hygiene.py`

Modeled on `check_pins.py`: typed, stdlib only, `main(argv, root)`, `KO` lines
and exit 1 on findings. It scans every file of `git ls-files` (or the files
given as arguments) line by line. Rules:

| Rule | Finding | Allowed |
|---|---|---|
| account in ARN | `arn:<partition>:<service>:<region>:<12 digits>` | `123456789012`, `000000000000`, `111122223333`, `444455556666`; `aws` (managed resources) never matches |
| account in bucket or registry | 12 digits inside an `s3://` or `arn:aws:s3:::` bucket name, `<12 digits>-<region>` (CDK/SAM naming) and `<12 digits>.dkr.ecr.` | the same accounts |
| CDK bootstrap bucket | the default bootstrap qualifier `hnb659fds` after `cdk-` | none |
| SSO profile or role | `AdministratorAccess-<digit>`, `<PermissionSet>Access-<12 digits>`, `AWSReservedSSO_<set>_<16 hex>` | none |
| MicroVM ID or endpoint | `microvm-` followed by eight hex digits (a full UUID or a truncated prefix), and `<uuid>.lambda-microvm.` | UUIDs `00000000-0000-0000-0000-` + twelve decimal digits, and the truncated prefix `00000000` of those fakes |
| network ID | `vpc-`, `subnet-`, `sg-`, `eni-` + 8 or 17 hex digits | `0123456789abcdef0` |
| local path | `<drive>:\` or `<drive>:/` followed by `Users`, `tools` or `Projects`; Git Bash `/<drive>/Users/`, `/<drive>/tools/`, `/<drive>/Projects/` | none |
| AWS access key | `AKIA` / `ASIA` + 16 uppercase letters or digits | keys ending in `EXAMPLE` (AWS documentation) |

- Binary files (a NUL byte or invalid UTF-8) are skipped, as `git grep -I`
  does. Lockfiles are scanned: nothing in them matches today, so there is no
  reason to exclude them.
- Findings print `path:line` and the rule, never the line: the gate must not
  echo an access key into a CI log.
- The module spells the CDK qualifier as a separate constant and the tests
  build every positive sample from pieces, so the gate scans its own files
  with no exclusion list.
- Machine-specific names (user names, project directories) are not in the
  gate: listing them would publish them. The path rules catch them where
  they appear, inside paths.

### D6. CONTRIBUTING without personal paths

Linux/macOS/WSL2 share the `make` workflow; Windows runs the same commands in
Git Bash. The optional `x86_64-pc-windows-gnu` host with `zig` as linker (for
machines without the Visual Studio Build Tools) is described with
`$RUSTUP_HOME`/`$CARGO_HOME` defaults and `<dir>` placeholders.

## Risks / Trade-offs

- [The gate misses an identifier shape it does not know] → The rules cover
  every shape found in this tree; new shapes are added as rules with tests.
- [A legitimate string matches a rule] → The allowlists are the documented
  placeholders; a new placeholder is an explicit, reviewed change to the
  module.
- [History still contains the old values] → Out of scope (Non-Goals); the
  owner decides how the public history starts.
