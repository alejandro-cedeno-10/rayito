## Why

`ai-agent-core` gave `sbx.agent` one runtime, OpenCode. The agent spike
(`docs/research/2026-10-agent-spike.md`) also ran a deepagents graph inside
a sandbox with Bedrock behind a `SecretGateway`, but only as a throwaway
script: no protocol, no permissions, no sessions, no limits. Teams that
already build agents with LangGraph want the same `sbx.agent.run()` /
`stream()` contract (closed events, hard limits, credentials only through a
gateway) with their own graph.

## What Changes

- **deepagents adapter** of the `AgentRuntime` port
  (`rayito/_agent/_deepagents.py`, `src/agent/deepagents.ts`): `DeepAgents`
  (`runtime=DeepAgents(entrypoint="pkg.mod:build")` or
  `runtime="deepagents"`), registered as `"deepagents"` in both registries
  and exported from `rayito` and `index.ts`. It writes one JSON config
  (`AGENT_STATE_DIR/deepagents/config.json`, 0600), a run script (the same
  `flock` as OpenCode, a `runtime_missing` check, `exec` of the venv Python)
  and sends the request on stdin. `mcp`, `raw_config`, `attach=True`, tool
  names deepagents does not have and patterns outside `bash` raise
  `InvalidArgumentException` / `InvalidArgumentError` before any RPC.
- **Runner** (`rayito/_agent/_runner/deepagents_runner.py`, package data;
  the template installs it at `/opt/agents/rayito/deepagents_runner.py`):
  speaks the Rayito JSONL protocol v1 (`{"v":1,"type":…}` with the event
  names plus `session`), keeps the protocol on a private copy of stdout so
  a user `print` cannot corrupt it, builds the model against the gateway
  (`ChatBedrockConverse`, `ChatAnthropic`, `ChatOpenAI`) with the
  placeholder key, enforces permissions with a `wrap_tool_call` middleware,
  stores sessions as `rda_<uuid4 hex>` and calls a user entry point with a
  `RunnerContext`.
- **TypeScript copy of the runner** generated by `scripts/gen_agent_assets.py`
  into `src/agent/assets/deepagents-runner.ts` (source and sha256), with
  `--check` in `make lint` and CI.
- **Pins**: `dev/local/agent/requirements-deepagents.txt` adds
  `langchain-openai` (and its `openai`, `regex`, `tiktoken`) without moving
  any existing pin.
- **Tests**: shared golden files `testdata/agent/deepagents-config.json`,
  `deepagents-run-commands.json`, `rayito-protocol-v1.jsonl` and its
  expected events; runner unit tests with deepagents stubbed in
  `sys.modules`; `make agent-runner-test` runs the runner with the real
  pinned venv on Linux arm64 and a fake chat model (CI `arm` job).

## Capabilities

### Modified Capabilities

- `ai-agent-runtime`: adds the deepagents runtime, its protocol and its
  runner.

## Impact

- New public symbol `DeepAgents` in both SDKs; no change to existing
  signatures. No new AWS call: a deepagents run costs what an OpenCode run
  costs (sandbox time plus model tokens through the gateway), already
  covered by the `sbx.agent` cost box.
- The template build that installs the runner and the venv belongs to
  `ai-agent-fast-start`; moving the requirements file into package data is
  coordinated there, because `dev/local/agent/Dockerfile` copies it.
